# Chapter 1 — From Idea to Upload — The Complete Production Path

*Every film travels the same road*

> "Amateurs start with a prompt. Studios start with a brief and end with a package."

## The Path

```
IDEA → STORY BRIEF → PACK/BIBLE SELECT → SHOT PLAN → REF IMAGES →
PROMPT ASSEMBLY (six-dimension blocks) → COMPILER (moderation + continuity + QA) →
GENERATE → REVIEW → REVISE (module-only) → ASSEMBLE + STINGS →
PACKAGE (title · thumbnail · description · pinned) → PUBLISH → LOG + CATALOG
```

Every step exists in Volumes I and II; Volume III is where they run as one continuous process. Skipping the Story Brief or the Compiler is where most productions fail.

## The Decision Points

- **LONG or SHORTS?** LONG = 16:9, four 15s clips + teaser + full package. SHORTS = 9:16, one 15s block per story, ~10 per pack.
- **Which universe?** Pick a canon pack (Vol II Ch19–22) or a genre pack (Ch14–18); this pre-loads camera, lighting, grade, audio, and identity defaults.
- **New premise?** Check the do-not-repeat catalog (Ch16) before writing.

## A Realistic Timeline (single creator)

| Stage | LONG episode | Shorts story |
|---|---|---|
| Brief + shot plan | 20–40 min | 5–10 min |
| Reference images | 15–30 min | reuse sheets |
| Prompt assembly | 30–60 min | 10–15 min |
| Generate + revise | variable | variable |
| Package + publish | 20–40 min | 10 min |

Batch the repeatable stages (Ch22): write a whole Shorts pack's briefs at once, generate in a run, package together.

## Roles (one person wears every hat)

Director (intent), writer (story), cinematographer (camera/lighting), designer (world/identity), performer-director (motion/dialogue), sound (audio), editor (assembly), and QA (the Compiler). The prompt is the document that briefs all of them at once.

## Golden Rule

Idea to upload is a pipeline, not a moment of inspiration. Run the same road every time and quality becomes a process instead of a lucky result.

# Chapter 5 — The Revision & Regeneration Workflow

*Fix the shot without breaking the film*

> "Change the one thing that failed — never rewrite the whole prompt."

## The Loop

```
Generate → Review → Diagnose (which module?) → Revise only that module →
Regenerate → Compare → Keep the winner → Log the fix
```

## Diagnose by Symptom

| Symptom | Failing module | Fix |
|---|---|---|
| Face/body changed | Identity | Strengthen IDENTITY LOCK; consistent @character_sheet |
| Camera drifts/zooms randomly | Camera | One primary move; specify held hero frame |
| Sun/shadows shift | Lighting | Single motivated source, held direction/colour |
| Trees/buildings morph | Environment | Strengthen continuity; name foreground/mid/back |
| Mouth off / emotion wrong | Dialogue/Lip sync | Reduce dialogue; add reaction time |
| Floating feet / limb fusion | Performance/Literalism | Simplify motion; avoid handoffs; safe prop phrasing |
| Blocked / no output | Moderation | Retry ladder (Ch4); visuals-only, then rebuild |

## Rules of Revision

- **One variable at a time.** Change the camera OR the light OR the line — not all three — so you learn what fixed it.
- **Keep the winners.** Save the seed/settings of any generation you like before iterating.
- **Isolate, then reintegrate.** If a full block fails, generate the scene bare, confirm it works, then add layers back.
- **Regeneration is normal.** Output is partly probabilistic; two or three passes to land a shot is expected, not failure.

## Log Every Fix

Record what broke, what changed, and what worked, then fold the lesson back into the preset or template (Vol II Ch26). A fix logged once becomes a mistake never repeated.

## Golden Rule

Precision beats brute force. Diagnose the one module that failed, change only that, and the rest of a working film stays intact.


# Chapter 6 — Beyond Fifteen Seconds — 30s, 60s & Multi-Scene Structure

*When the story needs more room*

> "Longer films are not longer prompts. They are more scenes, each still obeying the One-Action Rule."

## The Principle

A model reliably renders one clean action per clip. Longer films are built by **chaining clips** with strict continuity, then assembling them in the editor — not by asking one prompt to do everything. Each clip is still a six-dimension block with one action and a held hero frame.

## 30-Second Structure (2 scenes / 4–6 clips)

```
0–5s   Hook + world           (1–2 clips)
5–15s  Discovery + rising      (1–2 clips)
15–25s Conflict + decision     (1–2 clips)
25–30s Payoff + final image    (1 clip)
```

## 60-Second Structure (3–4 scenes / 6–10 clips)

```
Act I  (0–15s)   Ordinary world → inciting wonder
Act II (15–45s)  Journey → obstacle → low point
Act III(45–60s)  Decision → climax → resolution + final image
```

## Continuity Across Clips

Carry a **continuity bible** through every clip: identity locks, wardrobe, lighting direction and colour, environment, props, weather, and emotional progression. State "continuous from previous shot: same light, same wardrobe, same location" in each block. Use transitions (Vol II Ch13) to join scenes with intent.

## Assembly

Generate clips slightly long, trim on the cut, and let audio bridges (`TRANS_AUDIO_001`) carry across scene changes. Keep one grade across the whole film; change it only when time or location changes in the story.

## Golden Rule

Think in scenes and sequences, not one giant prompt. Many clean clips, strung with continuity, make a long film that holds together.

# Chapter 7 — Multi-Character Scenes & Ensemble Blocking

*More than one locked identity in the same frame*

> "Give the model one focal character and clear geography, or identities blur."

## The Challenge

Each additional locked identity in a frame raises drift risk. Manage it with clear blocking, a single focal subject per shot, and consistent reference sheets for every character.

## Blocking Rules

- **One focal subject per shot.** Others are present but secondary; cut to each for their beat.
- **Fixed screen positions.** Assign each character a side (hero frame-left, companion frame-right) and hold it across the scene for spatial clarity.
- **Eyelines match.** State who looks at whom so the geography reads.
- **Depth separation.** Foreground / midground / background placement keeps identities distinct.

## Coverage Pattern

```
Establishing two-shot (both, geography set) →
Single on A (their beat) → reaction single on B →
Two-shot for the shared moment → hero frame on the scene's emotional lead
```

Use `CAM_DLG_003` (two shot), `CAM_DLG_001` (over-shoulder), and `CAM_DLG_002` (shot/reverse) from Vol II.

## Ensemble Block Template

```
REF IMAGES: @character_sheet_A + @character_sheet_B + @storyboard + @environment_ref
[Emotion]. [Grade]. A (identity A, frame-left) [action]; B (identity B, frame-right) [reaction].
Focal: A. [Two-shot / OTS], [lens]. [Lighting]. [Camera move], held hero frame.
Eyelines: A → B. VFX/SFX. NARRATOR/DIALOGUE (label each speaker's VOICE_ID). ON-SCREEN TEXT: none.
Watermark: "CREATED BY AVIK STUDIO" — small subtle gold, lower-center.
```

## Golden Rule

Crowd the story, not the frame. One focal character per shot, fixed positions, matched eyelines — then let the cut carry the ensemble.

# Chapter 8 — Action, Chase & Combat Choreography

*Kinetic, readable, and non-graphic*

> "Action is a sentence of clean beats — not a blur of everything at once."

## One Action Per Beat

Break action into single-beat clips: approach, obstacle, impact, reaction, recovery, resolution. Each is its own six-dimension block with one move and a held frame. Readable geography beats chaotic intensity.

## Chase Structure

```
Setup (who chases whom, stakes) → obstacle 1 → near miss → obstacle 2 →
turning point → escape/capture → held hero frame
```

Tools: `CAM_FPV_001` (chase FPV), `CAM_TRACK_002` (lead track), `TRANS_WHIP_001` (whip pan between beats), `EDIT_ACTION` rhythm, `MUS_SPORTS`/`MUS_ADVENTURE`.

## Non-Graphic Combat

Keep it all-ages: conflict resolves in **light and motion**, not injury. Use the safe swaps — defeat/banish in light, shadow-beast for the threat, powerful for violent. Show impact through camera shake, energy, and reaction; never blood or gore. Heroes protect; threats dissolve into light or retreat.

## Impact Beat Template

```
REF IMAGES: @character_sheet + @storyboard + @environment_ref
Explosive resolve. [Grade]. [Hero] [single decisive action] against a shadow-beast that scatters into
light. Medium-wide, clear geography. [Lighting]. CAM_STATIC_002 low hero / quick CAM_PUSH_003, [lens],
held hero frame. VFX: FX_SPARKS, FX_HEAL_AURA (dispersal), light burst. SFX: impact whoosh, resonant
chord. NARRATOR: "[one line]". ON-SCREEN TEXT: none. Watermark: "CREATED BY AVIK STUDIO" — small subtle
gold, lower-center.
```

## Golden Rule

Momentum comes from clean, readable beats and motivated cuts — not from cramming a fight into one prompt. Keep it kinetic, keep it clear, keep it non-graphic.

# Chapter 9 — Emotional & Musical Sequences

*The feeling engine*

> "Sometimes the strongest scene has no dialogue at all — only image, motion, and music."

## Music-Led Sequences

When emotion leads, let music and image carry the story and drop dialogue. Map the sequence to a musical arc: quiet → build → swell → resolution. Cut on the emotional beat, not the bar line.

## Emotional Beat Mapping

```
Establish feeling → introduce tension → deepen → turning moment →
release → reflection → final image
```

Pair with `MUS_DRAMA`/`MUS_FANTASY`, `PACE_WONDER`, `TIME_EXPAND` (slow the peak), and `SIL_LOSS`/`SIL_REVEAL` for silence beats.

## The Growth Montage

`MONTAGE_GROWTH` in practice — child → learning → helping → confidence → hero: a series of short clips, each one emotional beat, unified by one grade and a single evolving music cue. Let a held final hero frame land the transformation.

## Silence as a Tool

A beat of true silence before a reveal or around a low point hits harder than any score. State it explicitly in AUDIO: "silence, then a single note."

## Emotional Sequence Template

```
Clip A  establish feeling  — image + ambience, no dialogue
Clip B  build              — motion + rising music
Clip C  turning moment     — CAM_PUSH_001, silence → single note
Clip D  release + final    — swell, held hero frame, warm narrator close
(One grade throughout; music evolves across the four.)
```

## Golden Rule

Feeling is a designed arc, not an accident. Map the emotion, let music and silence carry it, and end on the image the audience will remember.

# Chapter 10 — The Trailer & Teaser Engine

*Sell the feeling, withhold the story*

> "A trailer promises an experience. It never explains the whole film."

## Trailer Structure

```
Hook (striking image + question) → mystery (fragments, no context) →
character (who we'll follow) → conflict (the stakes) → epic beat (scale) →
silence (a held breath) → TITLE CARD → final hook (one last image/line)
```

Never reveal the resolution. Cut faster as it builds; drop to silence before the title.

## Teaser vs Trailer

- **Teaser (15s):** one image, one question, "[Title] — Coming Soon". Used inside a LONG package.
- **Trailer (30–60s):** the full structure above, for a series or season launch.

## Rhythm & Music

Start sparse, add layers, hit a swell at the epic beat, cut to silence, then title. Use `TRANS_LIGHT_001` and `TRANS_MATCH_001` between fragments; `MUS_MYTH`/`MUS_ADVENTURE` for scale.

## Trailer Beat Template

```
Frag 1  hook image + narrator question        (2–3s)
Frag 2  mystery fragment (no context)          (2s)
Frag 3  character in motion                     (2s)
Frag 4  conflict / stakes line                  (2–3s)
Frag 5  epic scale beat (CAM_CRANE_001)         (3s)
Beat    silence + single image                  (1–2s)
TITLE   held title card + brand accent
Frag 6  final hook image/line                   (2s)
(Each fragment is its own clean clip; assemble in the editor.)
```

## Golden Rule

Curiosity sells. Show enough to make them feel it, never enough to satisfy it — and always end on one last hook.

# Chapter 11 — Complex VFX & Creature Sequences

*Layered effects and living creatures at scale*

> "A creature convinces when it has weight, breath, and an effect on the world around it."

## Layering Effects with Purpose

Build complex shots in layers — base environment → atmosphere → primary effect → interactive detail → light response — each with a reason. Scale density to the beat (Vol II Ch12): high for the epic moment, reduced immediately after.

## Creature Performance at Scale

Give large creatures believable mass: `PERF_DRAGON_001` (heavy body, powerful wing beats, tail balance, landing impact), the Nebula Leviathan (slow, gentle, vast), robots (servo-precise, purposeful). The creature must affect its environment — wind from wings, dust on landing, water displacement, light from a glow.

## Interaction Rules

Effects and creatures interact with light, characters, and terrain: a dragon's fire casts moving light and heat shimmer; a portal illuminates the ground and pulls debris; a leviathan's passage bends starlight. State these interactions explicitly.

## Creature Beat Template

```
REF IMAGES: @character_sheet + @storyboard + @environment_ref
Awe. [Grade]. [Creature] (identity locked, PERF_DRAGON_001) [single action] while [environment reacts:
wind/dust/light]. Wide, subject scaled against a human/hero for size. [Lighting] with creature-cast light.
CAM_CRANE_001 / CAM_ORBIT_001, [lens], held hero frame. VFX: [FX layers, density high then settling].
SFX: deep body Foley, wing beats, environmental response. NARRATOR: "[one line]". ON-SCREEN TEXT: none.
Watermark: "CREATED BY AVIK STUDIO" — small subtle gold, lower-center.
```

## Golden Rule

Spectacle serves the story and obeys physics. Give creatures mass and let every effect touch the world — then pull the density back so the emotion, not the effect, is what the audience remembers.


# Chapter 12 — Building a Series Bible

*The single source of truth for a universe*

> "Every recurring world needs one document that everyone — including future you — obeys."

## What a Series Bible Contains

```
SERIES BIBLE: [Universe]
1. Premise & tone (one paragraph)
2. Universe rules (what is possible; magic/technology logic)
3. Cast bibles (identity locks, voice, personality, relationships)
4. World bibles (locations, palette, ambient audio)
5. Visual identity (GRADE_ID, signature lighting, camera language)
6. Audio identity (music family, narrator, signature sounds)
7. Episode format (LONG / SHORTS, length, structure)
8. Continuity rules (what must never change)
9. Series letter + numbering (A–E)
10. Do-not-repeat catalog link
11. Future roadmap (planned arcs)
```

## Why It Matters

A series bible is what keeps episode 40 consistent with episode 1. It locks the parts that must never drift (identity, palette, world rules) and frees you to be creative with the parts that should (story, emotion). Before writing any episode, open the bible; after shipping, update it.

## The Four Canon Bibles (Vol II Ch19–22)

Maani Adventures, The Infinity Trap, Neo-Vega, and Skyhaven each already have a starter bible in Volume II. Expand each with full cast reference sheets, a location index, and a continuity log as the series grows.

## Golden Rule

If it recurs, it belongs in the bible. The bible is the studio's memory of a universe — write it down once, obey it every episode.

# Chapter 13 — Season Architecture & Multi-Episode Arcs

*Shape a run of episodes, not just single films*

> "A season is a story made of stories."

## Season Structure

```
Ep 1        Introduction — establish world, cast, tone
Eps 2–4     Exploration — standalone adventures, seed the arc
Eps 5–8     Escalation — stakes rise, the arc surfaces
Eps 9–11    Major conflict — the season's central challenge
Ep 12       Resolution + final teaser for the next season
```

## Standalone vs Serialized

Most channels thrive on **episode-of-the-week with a light serialized thread**: each episode is a complete, satisfying story (so new viewers can start anywhere), while a subtle season arc rewards regular viewers. Keep 80% standalone, 20% arc in early seasons.

## The Season Arc

Choose one throughline per season (a mystery, a growing friendship, a returning threat). Plant it in Ep 1, touch it lightly through the standalones, escalate in the back half, resolve in the finale. Never let the arc break the "start anywhere" promise.

## Cliffhangers & Teasers

End arc-heavy episodes on a question; end the finale on a teaser image for the next season ("— To Be Continued"). Standalone episodes end complete, with a warm final image.

## Golden Rule

Design the season and the episodes together: complete stories that also add up to something larger. New viewers get a whole film; loyal viewers get a saga.

# Chapter 14 — Character Growth Across Episodes

*Characters evolve while staying unmistakably themselves*

> "Continuity preserves identity. Growth preserves interest. A series needs both."

## The Growth Timeline

```
Ep 1   baseline (who they are)
Ep 5   first real change (a lesson learned)
Ep 10  growing confidence / new ability
Ep 20  transformed role (leader, mentor)
```

Growth is gradual and motivated by story events — never a sudden personality swap.

## Consistency + Evolution

Lock the **identity** (face, voice, core traits, relationships) and evolve the **expression** (confidence, skill, role, wardrobe accents). Maani stays Maani — curious, loyal, the anatomy note always applied — but her courage can deepen across a 7-gate saga. Bolt stays Bolt, but earns Aegis Prime's trust over a season.

## Tracking Emotional State

Keep a simple per-character log: current emotional baseline, recent events that changed it, current goal, and relationship status. Reference it so an episode reflects what the character has been through.

## Growth Matrix (example)

| Character | Ep 1 | Mid-season | Finale |
|---|---|---|---|
| Maani | curious pup | brave guide | fearless leader of the 7 gates |
| Bolt | eager rookie | proven guardian | trusted partner to Aegis Prime |
| Mira | kind girl | confident rider | protector of Skyhaven's small creatures |

## Golden Rule

Change the character, not their identity. Audiences follow a series to watch someone they recognise become someone more.

# Chapter 15 — Franchise Continuity & Cross-Universe Rules

*Five universes, one studio, no collisions*

> "Shared canon may return. Specific events never repeat. Separate continuities never bleed."

## The Universe Map

Maani Adventures (A) · Hindu Mythology (B) · Robots & Transformers / Neo-Vega (C) · Fantasy Worlds / Skyhaven (D) · The Infinity Trap (E). Each has its own bible, palette, and rules.

## Shared vs Separate

- **Shared canon (reusable):** recurring leads and worlds — Maani & Sarvik, Bolt & Aegis / Neo-Vega, Mira & Ember / Skyhaven — may appear in many stories. Only the specific premise/event must never repeat.
- **Separate continuities (never bleed):** the two Infinity Trap lines — Vihaan + Ananta (long-form labyrinth) and Maani's 7-gate saga (Shorts) — are tracked apart; a beat from one must never appear in the other.

## Crossover Rules

Crossovers (e.g. Maani visiting Skyhaven) are allowed only when deliberate and logged, and only if they respect both bibles' rules and identities. Keep mythology (B) grounded in authentic legend and separate from the invented universes unless a special event is explicitly planned.

## Continuity Reports

Maintain a per-universe continuity log: major events, timeline, location history, unresolved threads, and any crossovers. Review it before writing so an episode never contradicts established canon.

## Golden Rule

Reuse the leads, never the premise; keep separate continuities separate. A franchise stays coherent when every universe obeys its own bible and the do-not-repeat catalog.

# Chapter 16 — The Do-Not-Repeat System in Practice

*The catalog that keeps every story original*

> "Recurring characters, never recurring stories."

## The Catalog

Maintain one living record of every story shipped, so no premise repeats:

```
CATALOG ROW: [ID] · [Series A–E] · [Title] · [one-line premise] · [characters] · [world] · [date] · [status]
```

Keep the two Infinity Trap continuities in separate sections so a long-form labyrinth beat never collides with a Shorts gate.

## The Pre-Writing Check

Before writing any new story: (1) open the catalog, (2) scan the target series for similar premises, (3) confirm the specific event/premise is new even if the characters recur, (4) only then write the brief. This single habit prevents the most common series failure — accidentally retelling a story.

## Recurring Leads, Unique Premises

Maani can have a hundred adventures; none may share the same specific problem-and-solution. Bolt can make many rescues; each must be a different rescue. The catalog is what makes "reusable characters" safe.

## Example Rows

```
A-071 · A · Maani and the Firefly Door · follows fireflies through a light-door · Maani · meadow · 2026-07 · live
C-072 · C · Bolt and the Falling Satellite · catches a falling satellite on a rooftop · Bolt · Neo-Vega · 2026-07 · live
E-073 · E · 7-Gate: The Emerald Gate · a trial of courage in light · Maani · Gate realm · 2026-07 · live
```

## Golden Rule

Check before you write. The catalog is cheap; a repeated story that viewers notice is expensive. Keep the leads, keep the world, change the premise — every time.


# Chapter 17 — The Publishing Calendar & Production Cadence

*Consistency is the algorithm you actually control*

> "A channel is a promise of rhythm. Keep the rhythm you can sustain."

## Consistency Over Volume

A steady, sustainable cadence beats sporadic bursts. Pick a schedule you can hold for months — one that survives a busy week — and protect it. Predictability trains both the audience and the platform to expect you.

## A Realistic Cadence (single creator)

| Format | Sustainable rhythm |
|---|---|
| Shorts | 3–5 per week (batched from one pack) |
| LONG episodes | 1 per week or biweekly |
| Series arc episode | 1–2 per month |

Adjust to your real capacity; a rhythm you keep beats an ambitious one you break.

## Batch, Don't Trickle

Produce in runs (Ch22): write a whole Shorts pack's briefs in one sitting, generate in a batch, package together, then schedule releases across the week. This decouples production days from publish days so a slow week never breaks the calendar.

## The Content Calendar

```
CALENDAR: [week] · [format] · [series A–E] · [title] · [status: brief/gen/package/scheduled/live]
Maintain 2–4 weeks of buffer so production pressure never dictates quality.
```

## Series Scheduling

Anchor each week with a recurring slot (e.g. "Maani Mondays"), so a series builds an appointment habit. Interleave universes across the week for breadth while keeping each series' slot consistent.

## Golden Rule

Ship on a rhythm you can keep. A dependable cadence, buffered by batching, compounds into a channel; heroic bursts followed by silence do not.

# Chapter 18 — Thumbnail & Title Science

*The click happens before the film plays*

> "The best film in the world does nothing if no one opens it."

## Thumbnail Principles

- **One clear subject** with a strong, readable emotion.
- **High contrast**, clean background, subject separated from it.
- **Minimal text** — three or four words, legible at phone size.
- **Mobile-first** — design for a thumbnail the size of a thumbnail.
- **Brand accent** — the magenta→cyan palette, consistent across the channel.
- Generate with a text-reliable image model (ChatGPT/DALL·E); the thumbnail should pose the same curiosity question as the hook.

## Title Principles

- **Curiosity + clarity.** Promise a feeling or a question without clickbait deceit.
- **Front-load the hook.** The interesting words first; assume truncation.
- **Consistent series signal.** A recognisable pattern ("Maani and the…") builds a brand.
- **Honest.** The title must match the film — misleading titles cost trust and retention.

## Pairing Title + Thumbnail

They should tell one story together, not repeat each other. If the thumbnail shows the wonder, the title poses the question; if the title states the stakes, the thumbnail shows the character who faces them.

## Iterate

Treat titles and thumbnails as testable: when a video underperforms relative to similar ones, try a new title/thumbnail. Keep a swipe file of your own best performers and study the pattern.

## Golden Rule

Earn the click honestly. One subject, one emotion, one legible question — matched by a title that promises exactly what the film delivers.

# Chapter 19 — Retention, Analytics & the First-Three-Seconds Rule

*Watch how people watch*

> "Retention is the story the audience tells you about your story."

## The Metrics That Matter

- **Retention curve** — where viewers drop; the shape tells you what worked and what lost them.
- **Average view duration / percentage viewed** — did the film hold?
- **Click-through rate** — did the thumbnail/title earn the open?
- **Rewatches & shares** — did the ending reward the watch?

Read them as feedback on craft, not vanity numbers.

## The First-Three-Seconds Rule

Most drop-off happens at the very start. Win the first three seconds: open on motion, mystery, or a striking image, pose the curiosity question immediately, and cut any slow logo intro before the hook. Story clips lead with the hook; the Intro Sting is short and never delays it.

## Reading the Retention Curve

- **Sharp early drop** → weak hook or misleading thumbnail; fix the first three seconds and title match.
- **Steady mid-drop** → pacing sags; tighten the middle, cut dead frames.
- **Spike up (rewatch)** → a moment worth studying and repeating.
- **Strong finish** → the ending rewarded viewers; keep that structure.

## Honest Framing

No tactic guarantees growth, and platform behaviour changes. Use analytics to improve the craft — better hooks, tighter pacing, honest titles — rather than chasing formulas. Consistent quality on a steady cadence is the only durable strategy.

## Golden Rule

Let the data teach craft. Win the first three seconds, hold the middle, reward the end — and read the curve to find the next thing to fix.

# Chapter 22 — Batch Production & Studio Automation

*Produce like an assembly line, decide like an artist*

> "Automate the repetitive. Reserve your judgment for the creative."

## The Batch Workflow

```
BRIEF BATCH    write a whole pack's Story Briefs in one sitting (check the catalog first)
PREP BATCH     confirm reference sheets; assign presets/packs per story
PROMPT BATCH   assemble all six-dimension blocks; run every one through the Compiler
GEN BATCH      generate in a run; mark keepers, flag re-gens
REVISE BATCH   fix flagged shots (module-only)
PACKAGE BATCH  titles, thumbnails, descriptions, pinned comments together
SCHEDULE       stagger releases across the calendar
```

Batching decouples production days from publish days — the single biggest lever for a sustainable cadence.

## Templates as Tools

The template bank (Vol II Ch23) is what makes batching fast: fill in only what's unique per story and let the structure carry the rest. Keep a personal library of your best-performing blocks and reuse them.

## Where Automation Helps

Automate the mechanical, not the creative: filename and version generation, catalog row updates, metadata scaffolding (description skeletons, hashtag sets), thumbnail layout templates, and checklist/QA reminders. Scripting (Python/TCL where you already work) can assemble metadata and organise outputs.

## Where Automation Must Not Reach

Story, emotion, casting, and the final QA judgment stay human. Automation assembles and organises; it does not decide whether a film is good. The Compiler flags issues; a person approves the film.

## Golden Rule

Build an assembly line for everything except taste. Automate the repetitive so your limited creative energy goes where only a human can add value.

# Chapter 23 — Workflow, Roles & Asset Management at Scale

*A place for everything, and a name for everything*

> "At scale, the studio that can find its assets beats the one that can't."

## Asset Structure

```
STUDIO/
  Series/<Universe>/       bible · reference sheets · location index · continuity log
  Presets/                 the Volume II libraries (versioned)
  Templates/               prompt + package templates
  Productions/<ID>/        brief · prompts · references · generations · package
  Published/               final videos · thumbnails · metadata
  Catalog/                 do-not-repeat catalog · analytics log
  Archive/                 superseded versions (never deleted)
```

## Naming & Versioning

Name everything predictably: presets `DEPT_SUBTYPE_NNN`; productions `SERIES-NNN`; files `PROJECT_SCENE_SHOT_Vxx`. Never overwrite a working generation or a bible — bump the version and keep history. Consistent names are what make search and reuse possible.

## Roles (solo or team)

Solo, you wear every hat in sequence. With collaborators, split along the pipeline: writer/director (brief + story), production (prompts + generation), post (assembly + package), and a continuity/QA owner who guards the bibles and the catalog. The bibles and catalog are the shared contracts everyone works against.

## Single Source of Truth

Each universe's bible and the do-not-repeat catalog are authoritative. When memory and a document disagree, the document wins — and then you update the document. This is how a studio stays coherent as it grows beyond what one person can remember.

## Golden Rule

Organise so the studio scales past your memory. Predictable structure, disciplined naming, versioned history, and authoritative bibles turn a pile of files into a studio.

# Chapter 24 — Model Migration Strategy

*Tools change; your system should not have to*

> "Build on principles, not on any one model's quirks."

## Stay Model-Agnostic

The ASPL grammar (Vol I) and the six-dimension block (Vol II) are universal; only the syntax changes per model. Keep the production specification stable and adapt the wording through an **adapter layer** — so a new model means new phrasing, not a new studio.

## Testing a New Model

Before adopting a model, run a fixed benchmark: generate the same three known shots (a dialogue close-up, an action beat, a creature/environment wide) that you've made before. Compare identity stability, motion quality, lip sync, and moderation behaviour against your current model. Decide on evidence, not hype.

## When to Switch

Switch or add a model when it clearly improves a capability you need (identity consistency, native audio, longer clips, better moderation pass-through) enough to justify re-learning its syntax. Often the answer is to use several models for their strengths (one for stills, one for motion, one for dialogue) behind the same spec.

## Protecting the Library

Keep presets described in universal, model-neutral language; store model-specific phrasing as adapter notes, not baked into the preset. When a model is deprecated, you update adapter notes — the library and the bibles survive intact.

## Golden Rule

Own the system, rent the models. Keep the spec, the library, and the bibles model-agnostic, and any model change becomes a syntax update rather than a rebuild.
